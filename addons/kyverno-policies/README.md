# Kyverno policies

Guardrails between the platform and product teams. Installed per cluster by
[applicationsets/kyverno-policies-appset.yaml](../../applicationsets/kyverno-policies-appset.yaml)
with the overlay matching the cluster's `environment`.

| Policy | dev | prod | Why |
| --- | --- | --- | --- |
| `protect-platform-baseline` | Enforce | Enforce | Product teams cannot change quota, limits, network policy or RBAC from the baseline with kubectl. They change `products/<name>/product.yaml` in a PR. |
| `require-requests-limits` | Audit | Enforce | Quotas and scheduling only work when containers declare resources. |
| `disallow-latest-tag` | Audit | Enforce | Git must say exactly what runs, so revert is a real rollback. |

The namespace baseline itself (quota, limits, network policies, RBAC, Pod
Security labels) is created explicitly by
[charts/product-namespace](../../charts/product-namespace/), not generated by
Kyverno: you can read it in Git and Argo CD shows it.

CI runs the prod overlay against every product's rendered manifests with the
Kyverno CLI, so most violations fail the pull request instead of the sync.
