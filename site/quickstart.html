Quickstart scripts

Production-ready fleet in a few commands

Pick a provider, set a few options, and download a filled-in env file plus a run script. They drive the repo's own bootstrap/<cloud>/up.sh: a hub with Argo CD and two spokes, dev and prod. Nothing here creates anything until you run it, and the run script does a --dry-run first.

1. Where should the fleet run?

All four tracks build the same thing: hub, dev and prod. Only the plumbing differs.

Provider

Cloud tracks bill by the hour, even overnight. Set a budget alert first, and keep the teardown script handy.

2. Basics

Names, region and the Git repo Argo CD will read.

Argo CD reads Git, not your laptop, and the run script pushes clusters/ to it, so use a repo you can push to. Empty = the upstream repo (fine for a dry run only).

3. Size and hardening

Two honest starting points. You can still edit every value in the env file.

Preset

On kind, size is whatever Docker gets. Give Docker about 8 GB RAM; the API servers only listen on localhost.

Comma-separated. Your current public IP: curl -s https://checkip.amazonaws.com, then add /32.

Open to the internet. The API servers stay authenticated, but anyone can reach them. Fine for a throwaway lab; for anything else, list your office or VPN egress IPs, or go private.

Argo CD profile

4. Review and download

Put both files in the same folder, then run bash run-aks.sh. It stops after the dry run and asks before creating anything.

    1. Read the dry-run output. It prints every command that would change something.
    2. Answer y to create the fleet. The script then commits and pushes clusters/.
    3. Easy to miss: until clusters/ is pushed, Argo CD still sees the old endpoints.
    4. Done for the day? Run the teardown script.

    What you get
    
      
    One hub, two spokes, everything from Git
    
      
      
        
    • Hub with Argo CDInstalled with Helm. The prod profile is HA: redis-ha, two or more server and repo-server replicas, PDBs, read-only default role.
      • 
        
    • dev and prod spokesRegistered declaratively as cluster Secrets with environment, region and upgrade-wave labels, listed in clusters/*.yaml.
      • 
        
    • Add-ons per environmentcert-manager, ingress-nginx, Argo Rollouts, External Secrets, metrics-server, kube-prometheus-stack, Kyverno.
      • 
        
    • Policies and tenantsNamespace requests through a PR; Kyverno generates NetworkPolicies, Pod Security labels and quotas.
      • 
        
    • ObservabilityAlloy on every spoke ships logs to Loki and Grafana on the hub; metrics from kube-prometheus-stack.
